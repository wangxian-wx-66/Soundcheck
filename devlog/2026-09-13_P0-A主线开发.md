> 范围：数据层 → Agent 管线端到端 → 双模式后端 API。**前端未开发（用户自行设计）**，本报告附完整 API 契约供前端对接。

## 一、交付模块

| 文件 | 职责 |
|---|---|
| `lib/db.mjs` | SQLite 三表（search_cache TTL 24h / qa_cache TTL 7天 / reports LRU 1000）+ WAL + 预编译语句 + 损坏自检重建（改名 .corrupt 后重建） |
| `lib/zhihu.mjs` | 知乎 HTTP 适配层：zhihu_search / global_search / question_answers / hot_list / quota；Bearer + 秒级时间戳；30001 限流重试一次；缓存键 sha256(api_type+query+count+filter+sort+api_version)（v2.4 修正口径）；single-flight 合并同 key 并发；结果精简（摘要截 600 字符控上下文） |
| `lib/llm.mjs` | DeepSeek（OpenAI 兼容，`https://api.deepseek.com`，模型 `deepseek-flash`）；function calling + `response_format: json_object` + 围栏/前后缀稳健解析 + 解析失败重问一次；60s 超时熔断；`LLM_MOCK=1` 内置脚本化 mock |
| `lib/gate.mjs` | 并发闸门：活跃分析信号量 ≤6 + 排队位置回调；上游在飞独立信号量（zhihu ≤4 / llm ≤4） |
| `lib/pipeline.mjs` | 主管线：run_id 贯穿、pending→running→done/failed 状态机、SSE 事件自增序号、工具预算 6 次、单轮 60s/全管线 5min 双熔断、question_answers 标准步骤代码级兜底注入（模型漏调时代码补拉标杆序）、三段 JSON 落 reports 表（**不含草稿原文**） |
| `server.mjs` | 保留全部 OAuth 路由 + 新增管线路由（见下方契约）；SSE 15s 心跳 + Last-Event-ID 续传 |
| `tests/pipeline.test.mjs` | 19 项测试：gate/db/zhihu/llm 单元 + 管线端到端（review/radar/兜底注入/预算封顶/降级/失败事件/落库回访/草稿不落库） |
| `scripts/smoke.mjs` | HTTP 级烟测（8 项）：本地 `npm run smoke`；**Sealos 部署后复用**：`SMOKE=1 LLM_MOCK=1 node scripts/smoke.mjs --url https://xxx.sealos.run` |

## 三、API 契约（前端对接用）

### 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/analyze` | 发起分析。Body：`{"mode":"review","question":"...","draft":"..."}` 或 `{"mode":"radar","question":"..."}`（question 可含问题 URL）。返回 `{"ok":true,"runId":"uuid"}`；参数错误 400 |
| GET | `/api/run/:runId/events` | **SSE** 事件流。断线重连带 `Last-Event-ID: <seq>` 头回放缓存事件；15s 心跳 `: ping` |
| GET | `/api/run/:runId/status` | 轮询兜底：`{"status":"pending|running|done|failed","seq":n}` |
| GET | `/api/report/:runId` | 报告回访（战报卡 URL 用 `?report=runId` 对接此端点）。done 前调用返回 404 |
| GET | `/api/hot` | 热榜 top10（选题雷达入口数据源，缓存 10 分钟） |
| GET | `/api/stats` | 运行时状态（活跃/排队/上游在飞——研究台排队提示用） |
| GET | `/api/health` | 健康检查（含 llm/zhihu 配置状态） |
| — | OAuth 路由 | `/api/oauth/status` `/api/oauth/start` `/auth/callback` `/api/oauth/logout`（官方脚手架原样） |

### SSE 事件类型（`data` 为完整事件对象 `{seq, ts, type, data}`，`id` 字段 = seq）

`queued {position}` → `start {mode, question, run_id}` → `budget {used, total:6}` → `parse {title_guess, arguments[], search_queries[]}` → `search_start {query, round}` → `search_done {query, adopted, cached, round}` → `evidence {chips[]}`（chip：`{type:'search', label:'22 赞 · L4 权威 · 作者名'}` 或 `{type:'benchmark', label:'社区序 #3 · …'}`） → `benchmark_start {question_url, injected?}` → `benchmark_done {count, cached, injected?}` → `final_start {}` → `done {rating, tool_calls, elapsed_ms}` | `failed {code, message}`

### 报告 JSON（`/api/report/:runId` 的 `result` 字段）

```
question_title  string                     rating  'S'|'A'|'B'|'C'
coverage.benchmarks[]   {rank, title, url, key_points[], evidence_level:'L1'}
coverage.recent[]       {title, url, votes, authority, key_points[], evidence_level:'L2'}
coverage.argument_map[] {argument, status:'covered'|'unique'|'blank', evidence_level, source_urls[]}   // 3-4 项，战报卡增量地图数据源
increment      {covered[], unique[], blanks[], amplify}
controversy.objections[] {objection, response, evidence:'real'|'inferred', source}   // real=真实评论证据（L3）
radar          {novelty, rigor, experience, resonance}   // 0-10；后两项启发式（meta.note 已声明）
meta           {confidence:'high'|'medium'|'low', note}   // 证据边界声明，战报卡底部展示
trace          {mode, tool_calls, qa_benchmark_pulled, generated_at}
```

### 前端约定（与计划书 §2.3/§六 对齐）

- 双模式 hash 路由：`#radar` / `#review`（切模式组件不卸载）
- 草稿仅存 sessionStorage（防抖暂存 + 回填），报告卡不含草稿全文——隐私承诺文案已定
- SSE 断线重连：`EventSource` 自动带 Last-Event-ID；「已续传，任务未重跑」提示位
- 排队态：`queued` 事件 →「前方 N 人」；`/api/stats` 可看全局水位
