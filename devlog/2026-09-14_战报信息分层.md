# 2026-09-14 · 战报信息分层：身份引导 + 视觉区隔 + 字段名泄漏修复

> 计划书 v2.21 → v2.22 | 触发：用户真 key 实测两项反馈——①杠精分歧文本出现「evidence_level 给到 L1」（内部字段名泄漏）；②「好几个说杠点的地方看不懂」（争议预演/评审团分歧/杠精找茬三处身份与视角不可辨）

## 一、问题与修复

### 1. 字段名泄漏（新病例：schema 词汇漏进用户文本）

- **层 1**：主审 + 杠精 prompt 文风段各加一条——「禁止把内部字段名（evidence_level / rating / unique / L1 等）写进给用户看的文本，用中文自然表述对应概念」，并澄清「JSON 键不受影响（值里的文本要管）」
- **层 3**：`humanize` 新规则 ④——字段名后**紧跟中文**时剥除（环视守卫 `(?=[\u4e00-\u9fff])`，防止误伤 `The coverage of this answer` 类正常英文）

### 2. 信息分层（页面顺序乱的最佳实践）

方案确认：**顺序不动，动的是「身份标注 + 视觉区隔」**。三个层次：

| 区块 | 修复后的引导文案 |
| --- | --- |
| 1 覆盖分析 | 「主审 Agent 检索了已有回答——这个问题的论点版图，别人写到哪了」 |
| 2 增量定位 | 「主审 Agent 的判断——你的增量在哪，怎么放大」（radar 模式自动切换） |
| 3 争议预演 | 「主审 Agent · 基于已有回答的评论区氛围，预判你会被杠的点」 |
| 4 评审团分歧 | 「主审与杠精是两个互相独立的 AI 评审——先看他们吵什么，再看杠精的改稿清单」 |
| 4 下 杠精找茬 | 标题加红底「杠」徽标 + 「杠精单独通读草稿后的攻击预演——发布前改稿清单」 |

视觉区隔：`.nit-row` 加 3px 红色左边界（针对你的攻击）vs `.cto-row` 默认边（社区氛围预判）——环境预判与个人攻击一眼分开。
