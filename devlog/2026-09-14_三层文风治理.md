# 2026-09-14 · 三层文风治理：战报文案去 AI 腔（提示词 + 结构 + 兜底）

> 计划书 v2.19 → v2.20 | 触发：用户实测截图反馈（战报「增量定位」「争议预演」文本 AI 味重：括号嵌套、斜杠枚举、方括号记号、名词化堆叠）
> 用户方案（提示词约束）经评估为「必要但不充分」，按三层最佳实践实施

## 一、三层方案

### 层 1：提示词约束（主战场，治源头）

- **主审 SYSTEM_PROMPT** 新增「写作风格」段：读者是准备发布的答主不是在读检索报告；完整短句有主谓宾；先结论后理由；明令禁止四种 AI 腔（括号嵌套限定 / 斜杠枚举 / 名词化堆叠 / 方括号记号），各配一个反例；末行声明「JSON 结构、字段名、证据等级标注不受本段影响」——**把文风要求与 schema 铁律隔离，降低互相挤占的风险**
- **杠精 CYNIC_PROMPT** 同款：毒舌老哥当面提点的口吻；objection 写成评论区真会出现的话（短、带情绪钩子）

### 层 2：结构放宽（给模型「用句子说话」的空间）

截断上限本身就是 AI 腔诱因——空间只够塞名词短语：

| 字段 | 原 | 新 |
| --- | --- | --- |
| argument_map.argument | 120 字 | 200 字 |
| increment.amplify | 600 字 | 900 字 |
| controversy.objection | 200 字 | 300 字 |
| controversy.response | 300 字 | 400 字 |

### 层 3：代码级兜底（`humanize`，治提示词漂移的 20%）

`lib/pipeline.mjs` 导出纯函数，normalizeReport 与杠精输出全量过一层，规则保守**只清洗记号不重组句子**：

1. 方括号记号 `[比分→局势→执行]` → 去括号留内容
2. 中文相邻斜杠枚举 `预算/青训/教练` → 顿号；**URL/数字/英文字母斜杠不动**（避免误伤 `https://` 与 `A/B`）
3. 全角嵌套括号 `X（Y（Z））` → `X——Y（Z）`（外层展开一层）
4. 多余空白归一

工程教训：字面正则里写全角括号多次踩「Unterminated group」（转义地狱），改 `new RegExp` 字符串构造（Unicode 转义 `\uFF08/\uFF09`）一次到位。

## 二、测试

- 单测 +6（43/43）：humanize 四条规则各一 + 边界（URL/数字/单层括号零改动）+ 端到端（mock 报告注入典型 AI 腔 → 管线输出无方括号残留）
- mock 报告（lib/llm.mjs）注入 AI 腔锚点：`（线性代数/概率论（矩阵论））`、`按[选教材→跟课程→做项目]`、`拆成[最小集合→项目倒逼→按需深挖]`——层 3 端到端可回归
- 烟测 14/14（JSON 结构、证据等级、杠精事件零回归——文风约束未破坏 schema 遵从）

## 三、遗留与边界

- **真 key 文风效果未实测**（mock 是脚本响应不经过真实模型）：部署前跑一次真 key 分析，人肉读「增量定位」「争议预演」是否仍带 AI 腔；若层 1 遵从度不足，靠层 3 兜底记号，深层的「名词化堆叠」无法正则清洗（需提示词再调）
- 名词化堆叠（「可复制性正面评估」类）只能靠层 1 治，层 3 无法安全重组语义——已知边界

## 四、改动文件

- `lib/pipeline.mjs`：两个 prompt 文风段 + humanize 导出 + normalizeReport/杠精接线 + 截断放宽
- `lib/llm.mjs`：mock 报告注入 AI 腔锚点
- `tests/pipeline.test.mjs`：+6 单测
