> 一句话：知乎答主按下发布键之前，AI 帮你预演这次开麦——已有回答覆盖了什么、你的真正增量在哪、评论区会怎么杠你。

## 一、创作思路与目标用户

### 要解决的问题

写回答之前，答主面对的是一个黑盒：这个问题底下已经有一百个回答，其中三个讲得很好，但你不知道它们讲了什么。结果是两种浪费——认真写了两小时，发布才发现核心观点早就被高赞回答写透；或者反过来，明明有真知灼见，却因为不确定而不敢下笔。

AI 生成内容泛滥让这个问题变得更严重：当「再写一篇」的成本趋近于零，「这篇有没有增量」就成了唯一值钱的判断。知乎官方持续治理低质 AI 内容、周源在财报里说「真人创作的独特价值在 AI 时代进一步凸显」——但「独特」不能靠感觉，需要工具来核验。

### 产品定位

发布前的信息增量体检。两种用法对应创作的两个时刻：

- **选题雷达**（写作前）：只输入问题，一两分钟出论点版图和机会评级。这个问题还缺好回答吗，值得写吗，往哪个方向写。
- **开麦评审**（发布前）：粘贴草稿，除了同样的体检，还会得到针对草稿的逐条攻击预演——评论区大概率先杠你什么，怎么改。

### 目标用户

认真答主：垂直领域的专业创作者。他们有表达能力和领域积累，缺的是发布前的一次核验。不宣称覆盖全体答主——随便写写的人和这个工具没有关系。

### 明确不做的事

- 不做 AI 代写。体检报告和改稿建议都给，最后动笔的是人——产品的立场是守护真人创作，不是替代它。
- 不做 AI 味检测。那是红海，且和社区叙事相悖。
- 不做浏览器插件。评委需要安装的东西都是理解成本。

## 二、核心体验（用户怎么用）

打开首页，三步：

1. **选入口**。选题雷达只填问题；开麦评审再粘贴草稿全文。热榜和每日机会榜上的问题可以直接点选。
2. **看研究台**（一到两分钟）。检索过程完全透明：AI 主管在六次检索预算内自主决定搜什么词，先拉取目标问题默认排序的前二十条回答拿到社区标杆序，再做定向检索验证论点覆盖深度。每一步检索、每一条证据实时可见。
3. **读战报卡**。四个区块按回答一个核心问题的顺序排列：

| 区块 | 回答的问题 | 关键元素 |
|---|---|---|
| 覆盖分析 | 别人写到哪了 | 论点版图色块（写透的、缺好回答的、空白），每个论点标证据来源并附原文链接 |
| 增量定位 | 你该往哪打 | 已覆盖、缺好回答、相邻空白三档清单加可执行建议 |
| 争议预演 | 社区会怎么杠 | 基于真实评论区氛围的预判，每条附应对建议 |
| 评审团分歧 | 两个 AI 吵了什么 | 主审与杠精各自独立评分，针对草稿的三条找茬就是改稿清单 |

顶部是 S/A/B/C 评级（很缺好回答到已被写透），底部是诚实边界声明：所有判断基于检索摘要而非全文，经验维度和共鸣维度是启发式估计。战报卡可复制链接永久回访，可一键生成分享海报。

## 三、技术方案

### 整体架构

单容器全栈（Node.js 22 原生服务端，零运行时框架依赖），部署于 Sealos，SQLite 持久化，SSE 推送实时进度。核心是一条有界的多 Agent 管线：

```
输入（问题 / 问题+草稿）
  → 主审 Agent 循环（LLM function calling，6 次工具预算）
     · 定位目标问题 → 拉取默认序前 20 条回答（社区标杆序）
     · 定向检索补强 → 验证标杆论点的社区覆盖深度
     · 证据不足自主改写检索词，充分即收束
  → 杠精 Agent（接力）：主报告完成后独立审阅草稿，预测最狠的 3 条反驳
  → 三段式报告 JSON → 战报卡 + 分享海报
```

### 三个关键设计决策

**双证据链**。搜索接口返回的是近期相关内容而非高赞标杆（实测 30 条样本最高 554 赞），单独用它会把「最近的」误判成「最好的」。解法是两条链互补：question answers 的默认排序代表社区共识排序（标杆序），搜索的富字段（赞数、权威等级、完整摘要）负责验证论点覆盖深度。报告里每个判断都标注证据等级，用户能看到结论的来源。

**有界 Agent 而非自由循环**。工具预算 6 次、单轮 60 秒、全管线 5 分钟双熔断，超时降级出报告而非挂死。演示和评审场景都经不起失控。

**诚实的降级**。评论字段命中率实测约 37%，未命中时争议预演明确标注「推导」而非伪装成真实评论；启发式估计的维度标「估算」小字。AI 不装全知是这个产品的信任前提。

### 工程细节（评委关心的稳定性）

- 额度纪律：搜索缓存 24 小时、标杆序缓存 7 天、请求去重，单次分析的工具调用预算为 6 次（搜索与标杆序拉取共享），启动时额度自检，余量低于两成自动跳过补强检索
- 断线续传：SSE 事件序号加 Last-Event-ID，刷新页面从断点继续，不重烧额度
- 并发闸门：活跃分析上限 6，八路并发实测零限流
- 隐私：草稿只存浏览器会话，服务端内存十分钟自清，数据库不落草稿原文，报告可分享但不含全文
- 安全：凭证全部环境变量注入，镜像白名单拷贝，非 root 运行，提交前密钥扫描

### 真实验证

真 key 端到端实测 28 秒出完整报告；线上全链路已验证（真 key 分析、机会榜、参数校验、OAuth 401 逻辑）；单元测试 47 项与冒烟检查 15 项全部通过。

## 四、使用的知乎开放能力

| 能力 | 用途 | 说明 |
|---|---|---|
| 知乎搜索 zhihu_search | 主管线核心检索 | 富字段（赞数、权威等级、排名分）做论点覆盖验证 |
| 问题回答摘要 question_answers | L1 证据层 | 默认排序前 20 条，社区标杆序的唯一依据 |
| 热榜 hot_list | 机会榜数据源 | 每 12 小时预计算「热榜上还缺好回答的问题」 |
| OAuth 用户数据 | 「我的创作」 | 登录答主的公开创作列表，可一键发起选题雷达；遵循本人身份限制，不代查他人 |

全网搜索接口已在适配层完成接入与缓存配置，作为主管线的备用通道预留，当前版本未启用。

## 五、与知乎社区生态的契合点

**给社区的内容质量做闸门**。知乎最大的资产是认真回答的人和沉淀下来的存量回答。试麦员把存量回答变成新答主的参照系：写之前知道社区已经聊到哪了，发布前知道自己的增量在哪。每多一个答主过这道体检，低重复度内容就少一批——这和官方治理低质 AI 内容的方向完全同向。

**回访原文而非替代阅读**。战报卡的每个论点都附原文链接，证据链的终点是知乎站内。工具把人送回社区，而不是把人留在工具里。

**OAuth 只取公开数据**。「我的创作」用授权用户的公开创作列表，本站不落库、不存储，登录是可选项而非门槛——计登录数但不拦人。

## 六、对社区用户的实际价值

- **省时间**：选题雷达一两分钟看清一个问题的回答版图，相当于替你读完前二十条回答的摘要。写不写、往哪写，当场有数。
- **保增量**：开麦评审把「我觉得有新意」变成「这个论点在社区还没人写透，有四条依据」。发布决策从赌博变成核验。
- **少挨杠**：争议预演和杠精找茬让答主发布前就看到攻击点，把绝对表述改成条件句、给推测标注边界——发布心态完全不同。
- **可传播**：战报卡是可分享的「体检报告」，海报生成在浏览器本地完成。答主晒体检报告本身就在传播「认真创作」的文化。

## 七、后续规划

赛后优先做两件事：评审团改稿建议（按战报逐条给修改意见，采纳权留给作者，不动声调）；OAuth 复盘模式（已发布回答的增量回看，用创作列表加本人评论数据）。更长线的是把机会榜做成日更的选题入口。
