# 试麦员 Soundcheck · UI 设计规范 v1.0

> 2026-09-13 定稿 | 设计稿（可打开查看）：[design/mockups.html](design/mockups.html)
> 实现对照：`public/styles.css`（tokens 逐值对应本文件 §二）

## 一、设计立场

**「知乎基因的企业级内容工具」**——参考 Notion / Linear / 飞书文档的内容工具语言，叠加知乎品牌蓝。评委看到的不是「AI 生成的渐变紫科技页」，而是一个克制、可信、信息密度高的创作工具。

历届知乎黑客松获奖作品的 UI 共性（调研结论）：报告式排版优于仪表盘式炫技；一个强记忆点（我们的：增量地图三色地块）优于处处是重点。

反 AI 味红线（实现时逐条自查）：
- 无渐变、无发光描边、无玻璃拟态、无网格光斑背景
- 选中态用 1px 描边 + 同色内环，不用色块填充
- 一张卡片最多一个彩色焦点，其余中性灰
- 数字 / ID / 检索词用等宽字体，与正文形成质感对比
- 不用 emoji 当功能图标（仅战报卡「杠 / 应」文字章为例外）
- 动效只有两种：状态脉冲点（1.6s）、hover 过渡（≤120ms）
- 空状态写一句人话 + 一个动作

### 字体

- 阴影仅一档：`0 1px 2px rgba(24,26,27,.05)`，仅 hover 浮起时使用；层级靠 1px 边框表达

## 三、页面一：双模式入口（首页）

布局（单列居中，内容宽 760px）：

1. **顶部条**（白底，下分隔线）：左侧品牌区 = 纯描边麦克风符号（26px 方章，圆点+竖线构成，无渐变）+「试麦员 Soundcheck」字标；右侧知乎登录入口（头像/登录态）
2. **Hero**（36px 上留白）：主标「开麦前，先试麦」（品牌蓝强调「先试麦」）+ 一行产品说明
3. **双模式卡**（两列等宽，间距 16px）：
   - 选题雷达（写作前）：问题输入框 + 主按钮「扫描论点版图」+ 耗时提示
   - 开麦评审（发布前）：问题输入（选填）+ 草稿文本域 + **隐私承诺**（12px 灰字 + 锁图标，紧贴按钮上方：「草稿仅存本次浏览器会话，服务器不留存」）+ 主按钮「开始试麦」
   - 选中态：1px brand 描边 + inset 1px 内环；右上角模式标签胶囊（「写作前」/「发布前」）
4. **热榜入口**（分隔线以下）：「从热榜选一个试试」+ 换一批；Top4 列表，前三名次号品牌蓝等宽字体，整行可点，右侧「选题雷达 →」

## 四、页面二：研究台（分析过程）

头部：标题「研究台」+ 当前问题（截断）+ 工具预算胶囊（mono `4/6`）+ 状态胶囊（品牌蓝脉冲点 +「分析中」）。

主体两列（左 feed 1fr / 右栏 236px）：

- **左侧时间线**：竖向步骤流（解析输入 → 检索①②… → 拉取标杆序 → 争议预演 → 生成报告）。节点态：完成=绿勾圆点；进行中=品牌蓝脉冲点；待办=灰描边。每步附耗时（mono 小字）、检索词胶囊（等宽、浅底）、采纳数与证据 mini chip（`88 赞 · L4` / 琥珀色「N 条带真实评论」）
- **右侧边栏**：证据充分度条（品牌蓝填充 + 阶段文字）→ 工具预算分段格（6 格，用过蓝/未用灰）→ 证据 chip 流（搜索证据实线框：`赞数 · 权威 · 作者`；标杆证据**虚线框**：`社区序 #N`）→ 底部证据等级图例（L1 标杆序 / L2 富字段 / L3 真实评论 / L4 AI 转述）
- **底栏**：mono 小字 `run_id · 事件 seq` + 续传/排队提示（绿：「断线已续传，任务未重跑」；排队：「前方 N 人 · 约 X 分钟」）

## 五、页面三：开麦战报卡（核心输出物）

自上而下六区：

1. **头部**：评级章（72px 方章，衬线大字母 B，brand 细描边浅底）+ 问题标题 + 对比规模行（「对比 20 条标杆回答（社区序）+ 20 条近期讨论 · 证据 L1×3 L2×4 L3×2」）+ 一句话结论条（浅底框）
2. **四维数值条**（四等分）：新颖度 / 严谨度（实色条）+ 经验密度 / 共鸣度（**斜纹条 + 「启发式」小字标注**——不假装摘要证据能评估内容质感）
3. **①覆盖分析 · 增量地图**：横向三色地块条（4 论点），灰=已被覆盖 / 蓝=独有（2px 品牌蓝竖边）/ 虚线斜纹=空白；每地块右上角 mono 角标（L1/L2/推导）；下方图例行 + 「点击看判断依据」提示
4. **②增量定位**：四行 tag+文本（已覆盖=灰章 / 独有=蓝实底章 / 空白=虚线章 / 建议=绿章）
5. **③争议预演**：「杠 → 应」配对行（左红「杠」章反驳、箭头、右绿「应」章应对），行底证据徽标：绿「L3 真实评论」/ 琥珀「推导」（不伪造佐证是产品主张）
6. **底栏**：mono 溯源（run_id、检索次数、生成时间、「判断基于检索摘要，点击论点对照原文」）+「复制链接」次按钮 +「生成分享海报」主按钮（P2 实现）

## 六、交互与状态约定

| 场景 | 行为 |
|---|---|
| 路由 | hash：`#radar` / `#review`，切换不卸载组件、不丢输入 |
| 草稿暂存 | sessionStorage 防抖 500ms，回页/刷新自动回填；关标签即清 |
| 发起分析 | 按钮转禁用 → POST /api/analyze → 切研究台视图 → EventSource 接 `/api/run/:id/events` |
| SSE 断线 | EventSource 自动重连带 Last-Event-ID；底栏提示续传成功 |
| 报告回访 | URL `?report=<runId>` 直接进入战报卡视图 |
| 错误 | 顶部一行红字提示（不弹窗），研究台显示 failed 事件原因 |
| 分享 | 复制 `origin/?report=<runId>` 到剪贴板 |

## 七、后端 API 对接点（详见 devlog/2026-09-13_P0-A主线开发.md 第三节）

POST `/api/analyze` → SSE `/api/run/:runId/events`（事件：queued/start/parse/search_start/search_done/benchmark_start/benchmark_done/evidence/final_start/done/failed）→ GET `/api/report/:runId`；热榜 GET `/api/hot`；OAuth：`/api/oauth/start`、`/api/oauth/status`。
