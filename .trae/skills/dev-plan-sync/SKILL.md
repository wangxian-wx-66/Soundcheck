# 开发进度同步（Dev Plan Sync）

开发计划书是项目的**唯一事实源（Single Source of Truth）**。任何 agent 会话都不应依赖对话记忆来推断进度——所有进度信息必须落盘在计划书里，保证任何新会话读一份文档就能精确接续。

## 触发时机

1. **会话开始时（必做）**：先读开发计划书（进度表 / 时间线 / 风险表），确认当前所处阶段、上一个已完成的门禁、下一个待办项，再开始工作
2. **完成任一工作项后（必做，立即执行，不许攒批）**：完成一个任务、通过一个门禁（Gate）、跑完一次实测、做出一个技术决策、遇到一个新的阻塞——都必须当场回写
3. **会话结束前（必做）**：核对本次会话产生的所有进度变化是否已全部落盘

## 回写规则（按事件类型）

### A. 完成任务 / 通过门禁
- 在计划书时间线或任务表中，将该项标记为完成：`~~原任务文字~~ ✅`
- 若有实测数据（延迟、命中率、额度等），**用实测值替换原假设值**，并标注「实测」字样与日期
- 不要删除原文字（划线保留），审计痕迹即原创性证据

### B. 发现计划与现实不符
- 修正错误假设时同步更新版本号与变更记录（如 v2.6 → v2.7），变更行写明：改了什么、依据是什么
- 全文搜索旧表述残留（同一个错误口径可能出现在多个章节），改一处必查全局

### C. 产出原始数据 / 测试结果
- 原始数据存入 `devlog/`（命名 `YYYY-MM-DD_主题.md`，含环境、方法、原始数值、结论）
- 计划书中只引用结论 + 指向 devlog 文件的链接，保持计划书精炼

### D. 新增风险 / 风险解除
- 更新风险表对应行的状态列：✅ 已解除 / 🔶 待处理，并写明对策与依据

### E. 记录决策
- 重要技术决策（选型、参数、架构取舍）写入计划书对应章节，格式：**决策 + 一句话理由 + 依据来源**（实测/文档/推断，注明哪个）

## 状态标记约定

| 标记 | 含义 |
|---|---|
| ✅ | 已完成 / 已验证 / 已解除 |
| 🔶 | 进行中 / 待验证 |
| ~~文字~~ ✅ | 原计划任务已完成（划线保留原文） |
| ⚠️ | 风险或需注意 |
| （实测 YYYY-MM-DD） | 数据来源标记 |

## 硬性纪律

- **立即而非事后**：每完成一项就回写一项。会话中断/压缩后，未落盘的进度等于丢失
- **数据不造假**：没测过的写「待实测」，测过的写实测值和日期。计划书里的每个数字要么有实测依据、要么明确标注为假设
- **先读后写**：新会话动工前不读计划书就开工，视为违规
- **版本单调递增**：每次实质修改计划书内容（非纯错别字）都递增版本号并在变更记录追加一行
